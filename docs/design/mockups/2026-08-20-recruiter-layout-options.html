招聘模块布局方案

问题不在配色也不在间距，在于把 1600px 全部拿来放单列内容。 题卡横跨整屏，题干只占左边三分之一，中间是大片空白，维度徽章和时长孤零零飘在右端—— 眼睛要横扫一整屏才能把「这道题问什么」和「要花几分钟」连起来。

  • 题卡宽度 1500px
  • 题干实占 35%
  • 中间空白 约 700px
  • 下半屏 全空

下面四个方案用同一批真实题目、同一个宽度渲染，第一个标签是现状对照。 挑一个告诉我编号即可，也可以说「A 的宽度 + D 的行密度」这种组合。

A · 限宽阅读流

内容区限制在 780px 左对齐，不再拉满。行长回到正常阅读区间，题干和时长一眼能连起来。

  • 收益改动最小，只加一个 max-width，其余结构不动
  • 收益行长受控，扫读效率最高
  • 代价右侧仍有空白，只是从「难看的空」变成「留白」

B · 主从双栏

左边一列题目，右边常驻当前题的完整细则。点一题右边就换内容，不用展开收起。

  • 收益面试中最好用：题目列表和当前题细则同时在屏，不用来回折叠
  • 收益横向空间用满，没有大片空白
  • 代价会前想通读全部题目时不如 A / D 直接，得逐题点
  • 代价改动最大，题卡组件要拆成列表项 + 详情面板两个

考察点
看拆解问题的路径，是否有假设与验证，而不是背结论。
评分标准
优秀：有假设有验证，结果能量化
合格：能说清现象和最终原因
不合格：只复述结论，讲不出过程
追问建议

参考答案要点
  • 定位手段（监控 / 日志 / 链路追踪）
  • 验证方式与回滚预案

C · 双列卡片

题目排成两列。横向空间填满了，纵向也短一半。

  • 收益横向填满，纵向压到现在的一半
  • 收益改动小，只改容器的 grid
  • 代价题目有先后顺序，两列会打断「从上往下问」的阅读方向
  • 代价展开某一题时会把同行另一题挤开，跳动明显

我的判断

B 主从双栏最贴合你定的场景。你选的是「面试中实时看」——那个场景下， 面试官需要的是「当前这道题的完整细则」常驻在眼前，同时能瞥见还剩几题。 折叠展开是在单列约束下的妥协，主从双栏直接消掉了这个妥协。

如果想小步走，A 限宽是性价比最高的一档：一行 CSS 就能把最刺眼的空旷解决掉， 结构完全不动。之后想升级到 B 也不冲突。

C 我不推荐——题目是有顺序的，两列会打断从上往下问的节奏，展开时还会把同行另一题挤开。 D 密度最好，但那套观感更适合「批量管理」而不是「面试中对着念」。
