招聘模块 · 交互方案调研

四种互不相同的交互模型。不参考现有实现，功能一个不少。

先说诊断

现在别扭的根源不是布局细节，是一套骨架在服务三种完全不同的场景： 面试前配置密集、可以慢；面试中双手忙、眼睛在候选人身上、看屏幕的时间很短； 面试后是阅读和决策。现在这三件事共用「左栏候选人 + 步骤 Tab + 双栏」， 于是每一件都只有六十分。另外步骤条长得像向导（编号 + 对勾）却不代表顺序也不代表进度， 题目用「列表 + 详情」这种文件浏览器的形态，而面试实际是线性推进的。下面四个方案，各自从不同角度拆这个矛盾。

方案 A

面试台 · 把「准备 / 实战 / 复盘」拆成三个形态

不再用 Tab 切换视图，而是切换模式。准备是一页配置表单； 点「开始面试」进入专门的面试台：一次一道题、题干放大、答案框紧贴题干下方、 键盘推进；面完直接进复盘报告。三个界面长得完全不一样，因为它们要干的事本来就完全不一样。

解决面试中不用找东西。题干、评分标准、答案框在同一屏同一视线内，按一下键就是下一题。
代价多一次模式切换。只想改一道题时也要进面试台，需要一个「随时退出」的出口。

面试台模式。左边一栏放候选人列表？没有——面试中只有一个人，屏幕全给他。

功能覆盖

  • 岗位增删改、JD、题目数量、维度权重与描述 → 全在「准备」页
  • 候选人增删改名、搜索、切换 → 岗位页的候选人列表，进面试台前选
  • 简历上传解析 / 粘贴文本 → 「准备」页第一块
  • 出题生成、重新生成、复制全部 → 「准备」页底部按钮，生成完直接进面试台
  • 逐题答案→ 面试台的核心，答案框常驻
  • 删除单题→ 面试台右上角「⋯」，或准备页的题目预览
  • 整段面试记录→ 复盘页顶部，和逐题答案二选一
  • 评价总分、雷达、逐题打分、优势风险、录用建议 → 复盘页
  • 候选人对比→ 岗位页，≥2 人已评价时出现
  • 进度顶部色带，颜色即维度
方案 B

单页文档 · 一个候选人就是一份从头滚到尾的文档

删掉步骤 Tab，也删掉题目的「列表 + 详情」。一个候选人对应一份长文档： 简历 → 八道题（全部展开，每道题自带答案框）→ 评价。 左侧一条粘性目录负责跳转。面试时就是一路往下滚，没有任何隐藏状态。

解决零隐藏。⌘F 能搜到全文，天然可打印/导出给同事，不存在「我刚才填的在哪个 Tab 里」。
代价长。十几道题要滚很久，面试中靠滚动定位比按一下键慢。

方案 C

漏斗看板 · 招聘本来就是漏斗，界面就长成漏斗

岗位内不再是候选人列表，而是五列看板：待传简历 / 待出题 / 待面试 / 待评价 / 已决策。 卡片是候选人，拖过去就推进状态。点开候选人从右侧滑出抽屉， 抽屉里是一条纵向流程。面试官关心的从来是「谁卡住了」，不是「谁排在第几」。

解决同时推进十几个候选人时，一眼看清全局和卡点。状态不用手动改，拖动即状态。
代价单人深度操作被挤进抽屉，宽度受限；只招一两个人时看板显得小题大做。

方案 D

面试时间线 · 一场面试就是一条对话

题目和回答交替排成一条时间线，像聊天记录。左边是 AI 出的题，右边是你记下的回答。 底部一个常驻输入框，回车即记录、自动推出下一题。 面完之后，这条时间线本身就是面试记录，不需要另外再粘贴一遍。

解决和面试的真实节奏同构。答案永远贴着题，不会记串行；面试记录天然生成。
代价跳题、回改弱一点；评分标准要靠侧栏或悬浮，不能常驻在题干旁边。

面完点「结束」，整条时间线就是评估用的面试记录——现在那个「粘贴整段面试记录」的框可以删掉。

功能覆盖

  • 岗位配置 → 独立设置页，和面试完全分开
  • 候选人增删改名、搜索 → 岗位页；一个候选人一条时间线
  • 简历→ 时间线第一条「系统消息」，可展开
  • 出题→ 生成后题目按顺序排队，逐条推出
  • 逐题答案→ 就是时间线上的「回答」气泡
  • 删除单题→ 题目气泡的「⋯」，或侧栏右键
  • 整段面试记录→ 不再需要手动粘贴，时间线即记录（仍保留导入口给线下面试）
  • 评价→ 时间线末尾追加一条「评估报告」，接着往下读
  • 跳题 / 回改→ 右侧题目栏点任意一题跳过去
  • 候选人对比→ 岗位页

怎么选

如果你…选因为
自己一个人面，面试中最看重顺手 A 面试台是四个里唯一为「双手忙、看屏幕时间短」专门设计的形态
希望结果能直接发给同事看 B 整份文档结构即导出结构，零隐藏状态，打印即成品
同时推进十几个候选人 C 漏斗是招聘的真实心智，拖动即状态，卡点一眼可见
想让「记录」这件事本身消失 D 时间线即面试记录，省掉「粘贴整段记录」这一步和它带来的归错题问题

A 和 C 不互斥：C 的抽屉里那个「进入面试台」就是 A。如果拿不定主意， C 做岗位层 + A 做候选人层是最完整的组合，代价是要实现两套界面。
